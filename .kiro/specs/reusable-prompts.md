# 再利用可能なプロンプト集

このファイルは、同様のspecs作成作業を再現するためのプロンプト集です。

## 1. 基本的なspecs作成プロンプト

### PRFAQ.mdからのspecs作成
```
PRFAQ.mdからspecsを作成したましたが、いずれかのステップでロジックギャップがあり、詳細なspecに落とせず私の説明が必要な場合は、[Question] タグを付けて質問を追加し、私が回答を記入するための空の [Answer] タグを作成してください。独自の判断や決定は行わないでください。計画を作成したら、私のレビューと承認を求めてください。承認後、その計画を 1 ステップずつ実行できます。各ステップが完了したら、計画のチェックボックスに完了マークを付けてください。また、作業内容のレビューを求めてください。
```

### 質問リストの整理
```
本QuestionとAnswerのリストをspecsファイル内に記述し、specsファイルを練り上げるためにQA内容をもとに再検討できるようにしてください。
```

### 既存specsの分析と追加質問
```
要件と設計とタスクの作業を進めるにあたり、不明でロジック的な判断ができなかった項目を分析してimplementation-question.mdにQAリストとして追加してください。
```

## 2. 効果的なプロンプトパターン

### A. 段階的specs作成プロンプト
```
以下の手順でspecsを作成してください：

1. PRFAQ.mdの内容を分析し、要件の不明点を特定
2. [Question]/[Answer]形式で質問リストを作成
3. 質問への回答後、requirements.md、design.md、tasks.mdを順次作成
4. 各段階でレビューと承認を求める
5. 実装時の判断困難項目を追加質問として整理

条件：
- 独自判断は行わず、不明点は必ず質問する
- 各ステップで明示的な承認を求める
- チェックボックス形式で進捗管理する
```

### B. 技術仕様明確化プロンプト
```
既存のspecsファイル（requirements.md、design.md、tasks.md）を分析し、以下の観点で実装詳細が不明な項目を質問リストとして整理してください：

技術的詳細：
- アルゴリズムの具体的な実装方法
- パフォーマンス要件の数値
- エラーハンドリングの詳細
- 状態遷移の条件

システム設計：
- コンポーネント間の連携方法
- データフローの詳細
- セキュリティ要件
- 運用・保守方針

実装戦略：
- 開発環境の前提条件
- テスト戦略
- デプロイメント方法
- 段階的実装の優先順位
```

### C. 質問カテゴリ化プロンプト
```
実装に必要な質問を以下のカテゴリで整理してください：

1. 技術環境・前提条件
2. 機能要件の詳細
3. 非機能要件（性能・セキュリティ）
4. システム設計の詳細
5. データ管理・プライバシー
6. エラーハンドリング・フォールバック
7. テスト・検証戦略
8. 運用・保守計画
9. 開発・デプロイメント戦略
10. ユーザーインターフェース詳細

各カテゴリで[Question]/[Answer]形式を使用し、回答後にspecsを更新する計画を提示してください。
```

## 3. 品質保証プロンプト

### specs完成度チェック
```
作成されたspecsファイルが以下の基準を満たしているかチェックし、不足項目を質問として追加してください：

Requirements.md:
- EARS形式の受け入れ基準
- 測定可能な要件
- 優先順位の明確化

Design.md:
- アーキテクチャ図
- コンポーネント詳細
- データモデル
- インターフェース仕様

Tasks.md:
- 実装可能な粒度のタスク
- 要件との紐付け
- 依存関係の明確化
- テスト戦略の組み込み
```

### 実装可能性検証
```
各タスクが以下の条件を満たしているか検証し、不明点を質問として整理してください：

- 具体的な成果物が定義されている
- 実装に必要な技術情報が揃っている
- 前提条件が明確である
- 完了条件が測定可能である
- 他のタスクとの依存関係が明確である
```

## 4. 使用方法

### 新規プロジェクト開始時
1. 「基本的なspecs作成プロンプト」を使用
2. PRFAQ.mdまたは要件概要を準備
3. 段階的にspecs作成を進行

### 既存specs改善時
1. 「技術仕様明確化プロンプト」を使用
2. 現在のspecsファイルを分析
3. 不明点を質問として整理

### 品質向上時
1. 「品質保証プロンプト」を使用
2. 完成度と実装可能性をチェック
3. 必要に応じて追加質問を作成

## 5. 成功のポイント

- **段階的アプローチ**: 一度にすべてを決めず、段階的に詳細化
- **明示的な承認**: 各段階で必ずレビューと承認を求める
- **質問の構造化**: [Question]/[Answer]形式で明確に整理
- **トレーサビリティ**: 要件からタスクまでの紐付けを維持
- **実装可能性**: 技術的な実現可能性を常に考慮
